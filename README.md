# debugger

[English](README.en.md) | [更新履歴](CHANGELOG.md)

『侍道4』の Mod を作るためのデバッグツールです。いくつかの機能をまとめた Mod で、機能ごとに `config.ini` で使うかどうかを選べます。

| 機能 | 内容 | 既定 |
| --- | --- | --- |
| [エラーログ](#エラーログerror_log)（`error_log`） | 例外を記録し、ゲームが落ちたときはミニダンプも書く | 使う |
| [引っかかりの記録](#引っかかりの記録jank)（`jank`） | いつもより時間のかかったフレームを見つけ、そのあいだゲームが何をしていたかを書く | 使わない |
| [声の記録](#声の記録voice_trace)（`voice_trace`） | キャラの声を鳴らすたびに、鳴ったか・鳴らなかったならなぜかを書く | 使わない |

どの機能を使っていても、他の Mod は [ノート](#他の-mod-から手がかりを残すノート) で手がかりを残せます。

## エラーログ（error_log）

ゲームの中で例外（アクセス違反など）が起きると、ゲームのフォルダ（`WayOfTheSamurai4.exe` があるフォルダ）の `logs/` に記録します。ゲームを起動してから終えるまでに例外が起きなければ、ファイルも `logs/` フォルダも作りません。

```
logs/error_<日時>_<プロセス番号>.log   … エラーログ（テキスト）
logs/crash_<日時>_<プロセス番号>.dmp   … ミニダンプ（ゲームが落ちたときだけ）
```

エラーログとミニダンプは、同じ回のものなら日時とプロセス番号が同じです。

エラーログの記録は2種類あります。

| 見出し | いつ書くか |
| --- | --- |
| `==== Exception #n (first chance …)` | 例外が起きた時点。ゲームが自分で処理して、そのまま動き続ける例外も含みます。同じ場所の例外は、2回目以降は 2, 4, 8, … 回目のときだけ `---- Exception … again at the same address …: occurrence n` の1行を書きます |
| `==== Fatal exception` | どこでも処理されずに、ゲームが落ちるとき。原因を調べるときは、まずこの節を見てください |

それぞれの記録に書くもの：

- 例外のコードと場所。ゲームの exe の中なら `WayOfTheSamurai4.exe+1234 .text (default VA 00401234)` のように、exe の既定のベースアドレス（`00400000`）に直したアドレスも書きます
- アクセス違反なら、読み書きしようとしたアドレスと、そのメモリの状態（解放済みなら `free (released, or never allocated)` など）
- 例外が起きた命令のバイト列
- 全レジスタと、それぞれが指す先（メモリの状態と先頭 32 バイト。先頭 4 バイトの値が、読み取り専用データを指していれば、仮想関数表かもしれないので `(possibly a vtable)` と書きます）
- スタックの先頭と、スタック上の戻り先らしい値（call の直後を指すもの）。スタックを順に調べて拾うので、関係のない値も混ざります

致命的な例外のときは、さらに次も書きます。

- ノート（他の Mod が残した手がかり。下記）
- 読み込まれているモジュールの一覧
- ミニダンプの結果

エラーログの先頭には、ゲームの exe のファイルサイズと SHA-256 を書きます。どの版の exe の記録かを確かめるのに使えます。

- 例外を握りつぶしたり、ゲームの命令やセーブを書き換えたりはしません。ネットワークへの送信もしません。
- エラーログとミニダンプには、exe と DLL のパスが含まれます。ミニダンプには、さらにゲームのメモリの一部（`full` ではすべて）が含まれます。共有するときは注意してください。

## 引っかかりの記録（jank）

ゲームの画面が一瞬止まる（フレームの表示が遅れる）ときに、その原因を探すための機能です。ゲームの最適化を進めるときに使います。既定では使いません。`config.ini` の `[jank]` で `enabled=1` にすると使います。

ゲームの1フレーム（画面を1枚表示してから次を表示するまで）ごとに時間を測り、いつもより時間のかかったフレームを見つけると、ゲームのフォルダの `logs/` に記録します。

```
logs/jank_<日時>_<プロセス番号>.log
```

そのために、ゲームの処理をしているスレッド（メインスレッド）をごく短い間（数マイクロ秒）止めて、何をしているところかを調べることを、1ミリ秒ごとに繰り返します（サンプリング）。時間のかかったフレームの間に取ったサンプルを数えて、どこで時間を使っていたかを割合で出します。そのぶんゲームが少しだけ重くなるので、ふだん遊ぶときは使わないでください。

時間のかかったフレームごとに、`==== Slow frame #<フレーム番号>: <かかった時間> ms` の節を書きます。

| 行・見出し | 内容 |
| --- | --- |
| `Timing` | 表示したフレームの処理（`Frame` の呼び出し）にかかった時間と、その前（次のフレームを待つ間、ウィンドウのメッセージ）の時間 |
| `Main thread` | メインスレッドが CPU で動いていた時間と、プロセスのページフォールトの数。CPU の時間がフレームの時間よりずっと短ければ、何か（ファイルの読み込みなど）を待っていたことになります |
| `Game` | ゲームの状態（タスクの状態関数、スクリプトの実行中か・その種類、マップの読み込み中か、ゲームの時間が止まっているか）。フレームの間に変わったときは、前と後の両方 |
| `Steps of the main loop` | メインループのどの段階にいたか（次のフレームを待つ、入力、ゲームの更新、描画、表示〔Present〕、タスクの切り替え など） |
| `Calls in game code that were running` | スタック上にあった、ゲームの中の呼び出し（戻り先のアドレス）。その呼び出しの中にいた割合です。直接の呼び出しなら、呼び先の関数のアドレスも書きます |
| `Where the main thread was executing` | 実行していたコード。ゲームの中なら関数（先頭のアドレスは前の詰め物から推定したもので、`~` を付けます）、DLL の中なら `<DLL名>!<近くのエクスポート名>+<ずれ>` |
| `Most common stacks` | 多かったスタック（内側から外側へ） |

アドレスは、ゲームの exe の既定のベースアドレス（`00400000`）に直したものです。サンプルはスタックを順に調べて拾うので、関係のない値（前の呼び出しの残り）が混ざることがあります。数サンプルしかない項目は誤差と考えてください。

ほかに、決まった間隔（既定は60秒）ごとに、その間のフレーム数・FPS・フレーム時間の分布（中央値 p50、p95、p99、最大）を1行で書きます。最適化の前後を比べるのに使えます。

- 時間のかかったフレームとみなすのは、既定では直近のフレームの中央値の 1.5 倍（少なくとも中央値 + 5 ms）以上かかったフレームです。30 FPS なら 50 ms、60 FPS なら 25 ms になります。
- 詳しく書くのは1分あたり 20 フレームまでです。それを超えた分は数だけ数え、次の節と要約の行に書きます。
- ゲームの命令やセーブは書き換えません。ゲームのフレームの関数を呼ぶ表の1か所だけを、時間を測る関数に向け直します。

## 声の記録（voice_trace）

キャラの声（店の人や会話の声、戦闘の掛け声など）が鳴らないときに、その原因を探すための機能です。既定では使いません。`config.ini` の `[voice_trace]` で `enabled=1` にすると使います。

ゲームのフォルダの `logs/` に、声1つにつき1行を書きます。

```
logs/voice_<日時>_<プロセス番号>.log
```

- スクリプトが鳴らす声（店の人や会話の声）は、鳴ったときも鳴らなかったときも書きます。
- それ以外の声（戦闘の掛け声など）は、鳴らなかったときだけ書きます（`log_played_game_voices=1` にすると、鳴ったときも書きます）。1分あたり `max_lines_per_minute` 行までで、超えた分は数だけを書きます。
- キャラの声を鳴らさない設定が切り替わったときも1行書きます。

1行には、時刻、キャラの番号（スクリプトで使う ID、NPC の番号、声の組）、声の番号、結果を書きます。鳴らなかったときは、止めた検査（キャラが声を出さない状態にされている、キャラの声を鳴らさない設定になっている、その声がない、同時に鳴らせるストリームが埋まっている など）と、そのときの状態（ストリームと音の枠の使用数）も書きます。

```
18:18:04.015 PlayVoiceSE: character ID 7 (NPC 1006), voice set 42, voice 38: not played: the voice is streamed and 5 streams are already in use [caller 0x00568e19, forced=yes; muted=no, streams=5/5, slots in use=5/24, record=streamed]
```

- ゲームの命令やセーブは書き換えません。声を鳴らす3つの関数の入口で、状態を読んで記録するだけです。
- 声を鳴らすたびにログを1行書くので、ふだん遊ぶときは使わないでください。

## 設定（config.ini）

`mods/debugger/config.ini` に、機能ごとの節（`[<機能名>]`）があります。`enabled=1` でその機能を使い、`0` で使いません。ファイルや項目がないときは、上の表の「既定」と、下の各項目の既定の値になります。

```ini
[error_log]
enabled=1
minidump=standard

[jank]
enabled=0
threshold_ms=0
sample_interval_us=1000
max_reports_per_minute=20
summary_seconds=60

[voice_trace]
enabled=0
log_played_game_voices=0
max_lines_per_minute=120
```

`[error_log]` の `minidump` は、落ちたときに書くミニダンプの詳しさです。既定は `standard` です。

| minidump | 中身 | 大きさの目安 |
| --- | --- | --- |
| `off` | 書かない | なし |
| `small` | 全スレッドのスタックとレジスタ、モジュールの一覧 | 数百 KB |
| `standard` | `small` に加えて、グローバル変数、レジスタやスタックが指す先のメモリ、メモリの確保状況 | 数 MB〜数十 MB |
| `full` | プロセスのメモリすべて | 数百 MB〜数 GB |

使えない値を書いたときは既定の値にして、`mod_loader.log` にそのことを書きます。
`standard` や `full` で書けなかったときは、`small` で書き直します。どのレベルで書けたかは、エラーログの「ミニダンプの結果」に出ます。
ミニダンプは WinDbg や Visual Studio で開けます。

`[jank]` の項目：

| 項目 | 内容 | 既定 |
| --- | --- | --- |
| `threshold_ms` | このミリ秒以上かかったフレームを記録する。`0` なら自動（直近のフレームの中央値の 1.5 倍、少なくとも中央値 + 5 ms） | `0` |
| `sample_interval_us` | メインスレッドを調べる間隔（マイクロ秒、250〜10000）。短いほど細かく分かりますが、ゲームが重くなります | `1000` |
| `max_reports_per_minute` | 1分あたりに詳しく書くフレームの数（0〜600） | `20` |
| `summary_seconds` | フレーム時間の要約を書く間隔（秒、0〜3600）。`0` なら書かない | `60` |

`[voice_trace]` の項目：

| 項目 | 内容 | 既定 |
| --- | --- | --- |
| `log_played_game_voices` | `1` なら、スクリプト以外の声（戦闘の掛け声など）も、鳴ったときに書く | `0` |
| `max_lines_per_minute` | スクリプト以外の声について、1分あたりに書く行の数（0〜6000）。スクリプトの声は数えず、いつも書く | `120` |

## 他の Mod から手がかりを残す（ノート）

他の Mod は、短い文（ノート）を debugger に残せます。debugger は直近の 64 件を覚えておき、ゲームが落ちたときにエラーログへ書きます（エラーログを使わない設定なら、どこにも書きません）。「どの場面の途中で落ちたか」などを知るのに使います。debugger が入っていなければ、何もしません。

[include/wots4/debugger.h](include/wots4/debugger.h) を自分の Mod にコピーして、次のように使います。

```cpp
#include <wots4/debugger.h>

extern "C" BOOL WINAPI Wots4ModInitialize(const wots4::ModContext* context) {
    wots4::debugger::connect(context);  // 初期化の中で一度だけ呼ぶ
    // ...
}

// どこからでも（どのスレッドからでも）。1件 160 バイトまで
wots4::debugger::note("scene change started");
```

ノートはそのままエラーログに書かれるので、英語で書いてください（エラーログは英語だけにしています）。エラーログには、次のように書かれます（`[ ]` の中は、ノートを残した Mod のフォルダ名）。

```
Notes from other Mods (last 64):
  20:14:36.902 thread 12392 [example] scene change started
```

## インストール

### 自動インストール（推奨）

1. ゲームを終了してください。
2. [WayOfTheSamurai4ModInstaller.exe](https://github.com/nagataaaas/wots4-mods/releases/latest/download/WayOfTheSamurai4ModInstaller.exe) をダウンロードして実行してください。
   - 「Windows によって PC が保護されました」と出たら、「詳細情報」→「実行」を押してください。
   - 管理者として実行してよいかの確認が出たら、「はい」を押してください（ゲームのフォルダに書き込むためです）。
3. 画面の案内に沿って進め、Mod の一覧で `debugger` を選んでください。↑↓ で移動し、Space で選び、Enter で確定します。

ModLoader も一緒に入ります。更新も同じ手順でできます。設定（`config.ini`）は引き継がれます。

4. `{侍道4インストールフォルダ}/mods/debugger/mod.dll` があることを確認し、ゲームを起動してください。

</details>

## アンインストール

1. ゲームを終了してください。
2. `{侍道4インストールフォルダ}/mods/debugger/` フォルダを削除してください。中の設定（`config.ini`）も消えます。

記録が要らなければ、`{侍道4インストールフォルダ}/logs/` の中の `error_*.log`・`crash_*.dmp`・`jank_*.log`・`voice_*.log` も削除してください。

## ビルド

必要なもの：Visual Studio 2022 以降（C++ によるデスクトップ開発）、CMake 3.25 以降

[wots4-mods](https://github.com/nagataaaas/wots4-mods)（ModLoader と Mod SDK）が要ります。次のどちらかでビルドします。

- **wots4-mods の中でビルドする：** このリポジトリを `wots4-mods/mods/debugger/` に置き、wots4-mods の README の手順でビルドします。
- **この Mod だけをビルドする：** wots4-mods のパスを `WOTS4_SDK_DIR` に渡します。

```bash
cmake -S . -B build -A Win32 -DWOTS4_SDK_DIR=<wots4-mods のパス>
cmake --build build --config Release
ctest --test-dir build -C Release -LE needs_exe
```
